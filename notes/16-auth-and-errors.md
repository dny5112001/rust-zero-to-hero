# 16 · Login, tokens and errors

## Storing passwords: hash, never save the real one

If your database leaks, real passwords must not leak with it. So we store a
**hash**: a one-way scramble. You can check a password against it, but you
can't turn it back into the password.

[`src/auth/password.rs`](../notes-api/src/auth/password.rs) uses **Argon2**, the
recommended algorithm for passwords:

```rust
let salt = SaltString::generate(&mut OsRng);           // random per user
Argon2::default().hash_password(password.as_bytes(), &salt)
```

- A **salt** is random extra data mixed in, so two users with the same password
  get different hashes (there's a unit test for that).
- Argon2 is **deliberately slow and memory-hungry**, so guessing billions of
  passwords is impractical.

Never use plain SHA-256/MD5 for passwords — they're built to be fast, which is
exactly wrong here.

## Login tokens: JWT

After login, the server hands out a **JWT** (JSON Web Token) — like a
**wristband at a festival**: show it at each gate, no need to log in again.

```
eyJhbGciOi...   .   eyJzdWIiOiI0Mm...   .   SflKxwRJSMeKKF2QT4fwpM...
   header              payload (claims)          signature
```

- The **payload** holds "claims": `sub` (the user id), `exp` (expires at), `iat` (issued at).
- The **signature** is made with `JWT_SECRET`. Change one character of the
  token and the signature no longer matches → rejected.
- The payload is only **encoded, not encrypted** — anyone can read it. Never put secrets in it.

[`src/auth/jwt.rs`](../notes-api/src/auth/jwt.rs) creates and checks tokens,
with tests for: round trip, wrong secret, expired token.

The client sends it on every request:

```
Authorization: Bearer eyJhbGciOi...
```

### The AuthUser extractor

[`src/auth/mod.rs`](../notes-api/src/auth/mod.rs) implements Axum's
`FromRequestParts` trait:

```rust
impl FromRequestParts<AppState> for AuthUser {
    type Rejection = AppError;

    async fn from_request_parts(parts: &mut Parts, state: &AppState) -> Result<Self, Self::Rejection> {
        let header = parts.headers.get(AUTHORIZATION) /* ... */ .ok_or(AppError::Unauthorized)?;
        let token = header.strip_prefix("Bearer ").ok_or(AppError::Unauthorized)?;
        let id = jwt::verify_token(token, &state.config.jwt_secret)?;
        Ok(AuthUser { id })
    }
}
```

Now **any** handler that takes `user: AuthUser` is protected — no token or a bad
token returns `401` before the handler runs. You can't forget the check.

### Good security habits in the code

- Login says "invalid email or password" for both a wrong email **and** a wrong
  password, so attackers can't discover which emails exist.
- Emails are trimmed and lower-cased so `Asha@Example.com` and `asha@example.com` are one account.
- The password hash is in `User` but **not** in `UserResponse`, so it can't be sent out by mistake.
- `JWT_SECRET` comes from the environment (in Kubernetes, a Secret generated by Terraform).

## One error type for the whole API

[`src/error.rs`](../notes-api/src/error.rs):

```rust
pub enum AppError {
    Validation(String),        // 422
    InvalidCredentials,        // 401
    Unauthorized,              // 401
    NotFound,                  // 404
    Conflict(String),          // 409
    Internal(String),          // 500
}

impl IntoResponse for AppError { /* status code + {"error": "..."} */ }
```

Handlers return `AppResult<T>` (= `Result<T, AppError>`) and use `?` everywhere.
`From` conversions turn `sqlx::Error` and `validator::ValidationErrors` into
`AppError` automatically. For `Internal`, the real cause is **logged** but the
client only sees "internal error" — never leak database details to users.

## Try it

1. Log in, copy the token, and paste it into [jwt.io](https://jwt.io) — you can read the payload, but you can't change it without breaking the signature.
2. Set `JWT_TTL_SECONDS=10`, restart, log in, wait 80 seconds (the library allows 60s of clock leeway), and call `/notes` → 401.
3. Add a `GET /me` endpoint returning the current user's email.

## Remember

- Store Argon2 hashes with a random salt — never passwords.
- JWT = a signed wristband: readable by anyone, unforgeable without the secret.
- One `AppError` enum + `IntoResponse` = consistent, safe error responses.
